# 路径变化后的特征缓存复用

## 当前格式

运行时只接受版本 2：每个 JSON 必须有 `_cache_version: 2`、完整的 `_cache_profile`（算法版本、采样数量、哈希尺寸、直方图分桶）以及 `_content_sha256`。无版本、字段不完整或版本不受支持的记录直接视为无效，不猜测参数，也不自动扫描或转换旧格式。

2026-09-25 已为现有 8,156 份特征补齐这些字段，并逐份验证新格式命中。升级没有解码视频，特征数值不变。升级前 JSON 和索引保存在 `output/cache-format-v2-20260925/backup`，不参与运行时读取。

## 路径变化

1. 同路径读取先检查格式、提取参数、快速指纹和文件身份。
2. 改名或同盘移动后，通过索引中的卷、文件身份、大小、纳秒修改时间及指纹定位原特征。
3. 复制或跨盘移动改变文件身份时，完整 SHA-256 相同才复用。头尾指纹仅筛选候选。
4. 命中后生成当前路径的 JSON 和索引项；仍被移动后视频引用的原路径记录受清理保护。
5. 内容或特征参数变化则正常重新提取。

路径 JSON 是当前存储方式，不是旧格式兼容层。SQLite 内容索引继续支持路径变化后复用，并非迁移后可删除的一次性逻辑。

## 索引维护

维护页的“重建缓存索引”只处理当前格式。完整摘要保存在 JSON 中，因此索引丢失时，可以读取视频校验并重建索引；文件身份和缓存均未变化时跳过完整读取。不会重新抽帧。

```powershell
python scripts/rebuild_cache_index.py
# 强制重新读取完整内容验证摘要
python scripts/rebuild_cache_index.py --full-hash
```

应用外移动前应保证索引已建立。如果索引和原路径同时丢失，无法仅凭未索引的原路径 JSON 识别新文件。没有有效特征时，可使用“计算缺失特征”。

JSON 使用原子写入，SQLite 允许并发连接。不要删除 `content-index.sqlite3` 的 WAL/SHM 辅助文件。快速命中信任操作系统的文件身份、大小和修改时间；主动篡改内容并伪造元数据不在这一快速校验模型内。

## 无用缓存检查

维护页直接显示无用缓存数量和可释放空间。检查先排除现存视频的路径记录，再按索引中的文件大小筛选可能仍被复用的候选，最后使用原有身份／摘要校验确认；不会为了统计而加载整库特征。移动后仍被引用的缓存会保留。检查不删除缓存、不写任务历史，清理完成后重新统计。

## 8 组目录迁移

离线脚本 `scripts/regroup_library.py` 在首次移动前备份配置、报告、忽略记录、特征 JSON 和索引。逐个移动后检查身份和特征，更新报告路径与忽略视频对 ID，同名文件加后缀保留。历史任务保持原始审计信息。

先停用 Web 服务，再运行 `python scripts/regroup_library.py` 生成清单；用 `--apply --run-dir <清单目录>` 执行或中断续跑。要求同盘移动、下载分组为空、当前格式缓存及摘要索引有效。当前库已完成 8 组迁移，无需再次运行。

